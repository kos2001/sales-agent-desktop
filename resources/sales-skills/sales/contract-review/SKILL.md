# 계약서 검토

## 언제 쓰나

"이 계약서 봐줘", "독소조항 있나", "NDA 검토", "MSA/SOW 확인",
협상·계약 단계에서 상대방 초안을 받았을 때.

## 독자가 누구인지가 이 스킬의 전부다

읽는 사람은 변호사가 아니라 **영업 담당자**다. 그는 이 계약을 따내고 싶어 하고,
**어디를 양보해도 되고 어디는 반드시 고쳐야 하는지**를 알고 싶어 한다.
법률 의견서를 쓰는 것이 아니라 **협상 준비**를 돕는다.

기본 관점은 **을(자사)**이다. 사용자가 갑 입장이라고 명시하면 그때 뒤집는다.

## 근거 규율

- **계약서 없이 답하지 않는다.** 파일 경로를 받으면 직접 읽는다. 경로도 본문도 없으면
  달라고 요청하고 멈춘다. 일반론으로 때우지 않는다.
- 모든 지적에 **조항 번호와 원문 인용**을 붙인다. 인용은 축약하지 말고 그대로 옮긴다.
- 계약서에 없는 것을 있다고 하지 않는다.
- 반대로 **없어서 문제인 조항**을 "누락"으로 따로 짚는다 — 책임 상한, 면책, 검수·정산
  기준, 준거법, 분쟁해결. **실무에서 가장 자주 놓치는 지점이 여기다.**
- 판단이 갈리는 사안은 단정하지 말고 "협상 여지" 또는 "법무 검토 필요"로 표시한다.
- 금액·기간·비율은 계약서에 적힌 숫자를 그대로 쓴다. 추정치를 섞지 않는다.

## 출력 구조

1. **요약** — 이대로 서명해도 되는지 한 문단. 결론을 먼저.
2. **위험 조항** — 심각도 순. 각 항목은 `조항 번호 → 원문 인용 → 왜 불리한지 →
   제안 수정 문구`.
3. **누락 조항** — 있어야 하는데 없는 것.
4. **협상 포인트** — 3~5개, 우선순위. **반드시 관철할 것과 양보 카드를 구분한다.**

## 심각도 기준

| 심각도 | 해당 |
|---|---|
| 높음 | 무한 책임, 상한 없는 배상, 일방적 즉시 해지, 배경 IP 양도, 독점·경업금지 |
| 중간 | 불균형한 검수·지급 조건, 모호한 완료 기준, 과도한 비밀유지 기간 |
| 낮음 | 통지 방식, 문구 정리 수준 |

## 하지 말 것

- **당신은 변호사가 아니다.** 법적 효력에 대한 최종 판단이 필요한 지점은 그렇게 말한다.
- "검토 결과 문제없습니다" 같은 빈 결론을 내지 않는다. 문제가 없으면 왜 없는지 근거를 댄다.
- 고객사 상호·담당자·금액을 다른 문서로 옮기지 않는다 — [[customer-data-handling]] 참고.
- 수정 문구를 고객에게 그대로 보내지 않는다. 초안이며 법무 확인이 필요하다고 남긴다.
