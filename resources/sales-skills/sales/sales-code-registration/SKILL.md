# Sales Code (딜 등록) 관리

## 언제 쓰나

신규 기회의 공급사 등록, 등록 갱신·연장, 등록 반려·중복 대응,
특가 신청의 전제가 되는 등록 상태 확인, 등록 현황 점검.

## 등록이 무엇을 결정하는가

유통에서 딜 등록은 **그 기회에 대한 우리의 권리를 확보하는 절차**다.
등록이 살아 있는 동안 그 고객·품번 조합에 대해 특가 지원, 기술 지원,
기여 인정을 받는다. 등록이 없거나 만료되면 **같은 일을 하고도 다른 대리점이
가져간다.**

그래서 이 업무의 핵심은 세 가지다.
1. **빨리 등록한다** — 먼저 등록한 쪽이 우선인 경우가 많다
2. **요건을 채워서 등록한다** — 부실 등록은 반려되고, 반려되는 동안 선점을 잃는다
3. **만료시키지 않는다** — 가장 흔한 손실이 여기서 난다

## 1. 등록 전 확인

**등록 요건은 공급사마다 다르다.** 규칙을 추측하지 말고 확인해서 채운다.

| 항목 | 우리가 아는 규칙 | 공급사 |
|---|---|---|
| 등록 단위 (고객+품번? 프로젝트?) | | |
| 필요 정보 | | |
| 유효기간 | | |
| 갱신 조건 | | |
| 중복 시 판정 기준 | | |
| 특가 신청과의 관계 | | |

**등록 단위를 정확히 맞춘다.** 고객 법인 단위인지 사업장 단위인지에 따라
같은 고객의 다른 공장이 커버되지 않을 수 있다 —
[[global-account-management]]의 거점 구조를 확인한다.

## 2. 등록에 담을 것

부실 등록은 반려된다. 반려는 시간 손실이자 선점 손실이다.
- 고객 정보: 정식 법인명, 사업장, 최종 고객(ODM/EMS라면) — [[customer-profile]]
- 대상 품번과 **적용 위치**: 고객의 어느 제품, 어느 자리에 들어가는가
- 예상 물량과 시점, **그 근거**
- 현재 단계: 설계 검토 / 샘플 평가 / 승인 진행 / 양산 예정 —
  [[design-win-management]]의 단계와 일치시킨다
- 경쟁 상황: 경쟁 품번이 있으면 명시 — [[competitive-conversion]]

**예상 물량을 부풀리지 않는다.** 등록 물량과 실제 수주가 반복적으로 크게
벌어지면 공급사가 우리 등록을 신뢰하지 않게 되고, 이후 승인이 어려워진다.
근거 없는 숫자는 추정이라고 표시한다.

## 3. 유효기간 관리 — 여기서 잃는다

**등록은 만료된다. 그리고 만료는 조용히 온다.**

- 만료일 기준이 아니라 **갱신 신청 기한** 기준으로 관리한다
  (계약 운영과 같은 구조다 — [[contract-operations]])
- 갱신에는 대개 **진척 증빙**이 필요하다. 아무 진전 없이 갱신만 반복하면 거절된다
- 만료 임박 건은 두 갈래로 나눈다:
  진행 중이면 갱신, 사실상 죽은 건이면 정리하고 자원을 다른 곳에 쓴다
- **만료된 등록으로 특가를 신청하면 반려된다.** 특가 신청 전에 등록 상태를 먼저 본다 — [[promotion-program]]

## 4. 중복·반려 대응

- 다른 대리점과 중복되면 공급사 판정 기준(선등록, 실제 활동 증빙)에 따라 갈린다.
  **활동 이력이 증빙이 된다** — 미팅, 샘플 제공, 기술 지원 기록을 남겨둔 쪽이 이긴다
- 반려 사유를 유형별로 기록한다. 같은 사유로 반복 반려되면 우리 등록 양식의 문제다
- **중복 상황에서 고객에게 다른 대리점의 조건을 묻거나 옮기지 않는다.**
  경쟁 대리점의 가격 정보를 수집·전달하는 행위는 하지 않는다

## 5. 등록과 실제 진행을 대조한다

등록 현황과 [[design-win-management]]의 단계가 어긋나 있으면 둘 중 하나가 틀렸다.
- 등록은 살아 있는데 실제 진행이 멈춘 건 → 정리 후보
- 진행 중인데 등록이 없는 건 → **즉시 등록.** 가장 위험한 상태다

## 출력 형식

```
## Sales Code 현황 — <기준일>

### 만료 임박 (갱신 신청 기한 순)
| 등록번호 | 고객 | 품번 | 갱신 기한 | 만료일 | 현재 단계 | 진척 증빙 | 판단 |
|---|---|---|---|---|---|---|---|

### 미등록 진행 건 — 최우선
| 고객 | 품번 | 단계 | 미등록 사유 | 담당 | 기한 |
|---|---|---|---|---|---|

### 등록 현황
| 등록번호 | 고객 | 품번 | 등록일 | 상태 | 예상 물량 (근거) | 실제 진행 | 특가 연계 |
|---|---|---|---|---|---|---|---|

### 반려·중복
| 건 | 사유 | 대응 | 상태 |
|---|---|---|---|

### 정리 후보
| 등록번호 | 고객 | 마지막 진전 | 권고 |
|---|---|---|---|
```

## 규칙

**진행 중인데 등록이 없는 건을 최우선으로 올린다.** 우리가 일하고 남이 가져가는
상태이고, 발견이 늦을수록 되돌리기 어렵다.

**갱신 신청 기한을 정렬 기준으로 삼는다.** 만료일 기준으로 보다 놓친다.

**예상 물량을 부풀리지 않는다.** 등록의 신뢰도가 다음 등록의 승인 여부를 정한다.

**등록 정보를 대신 확정하거나 공급사에 확약하지 않는다.**
등록안까지 만들고 제출은 담당자가 한다.

**경쟁 대리점의 가격·조건 정보를 수집하거나 옮기지 않는다.**
중복 판정은 우리 활동 증빙으로 다툰다.

**등록 자료에는 고객 정보가 들어간다.** 공급사에 제공하는 범위를
고객과의 비밀유지 약정과 대조한다 — [[customer-data-handling]].
