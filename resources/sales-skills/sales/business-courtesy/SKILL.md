# 고객 선물 · 접대 관리

## 언제 쓰나

명절·연말 선물 계획, 식사·행사 접대 검토, 고객 방문 시 기념품,
고객 초청 행사. 그리고 **하기 전에 판단이 필요할 때**.

## 이 스킬의 전제

선물과 접대는 관계 유지의 관행이지만, 동시에 **법과 사내 규정이 정면으로 다루는
영역**이다. 잘못되면 담당자 개인과 회사가 함께 책임진다.

그래서 이 스킬은 "어떻게 하면 되는가"보다 **"해도 되는가"를 먼저 판정**한다.
판정이 애매하면 하지 않는 쪽이 기본값이다.

**이 스킬은 금액 한도를 만들지 않는다.** 한도는 사내 규정과 관련 법규에 있고,
그 값은 개정된다. 규정을 확인해서 채우고, 확인 못 했으면 진행하지 않는다.

## 1단계 — 금지에 해당하는지 먼저 본다

아래 중 하나라도 걸리면 **금액과 무관하게 하지 않는다.** 다음 단계로 넘어가지 않는다.

**대상으로 인한 금지**
- 공무원, 공공기관·공기업 임직원
- 그 밖에 관련 법규가 적용 대상으로 정한 직군
- 상대 회사가 수령을 금지하는 정책을 두고 있는 경우
  (많은 다국적 고객이 전면 금지 정책을 둔다 — [[global-account-management]])

**시점으로 인한 금지**
- 입찰·견적·계약 협상이 진행 중일 때
- 클레임·감사·품질 이슈가 진행 중일 때
- 승인·인증 심사가 진행 중일 때

**형태로 인한 금지**
- 현금·상품권 등 현금성
- 개인 계좌·개인 주소로 가는 것
- 상대의 직무상 판단에 대한 대가로 읽힐 수 있는 것
- 기록에 남기기 곤란한 것 — **기록 못 할 것이면 하지 않는다는 뜻이다**

**해외 고객은 그 나라 법이 추가로 적용된다.** 반부패 법규는 국외 행위에도
적용되는 경우가 많다. 해외 건은 사전에 법무 확인을 거친다.

## 2단계 — 규정 확인

| 항목 | 우리 규정 | 확인처 |
|---|---|---|
| 1인당 한도 (선물) | | |
| 1인당 한도 (식사·접대) | | |
| 사전 승인 필요 기준 | | |
| 승인권자 | | |
| 기록·보고 방식 | | |
| 해외 건 추가 절차 | | |

**빈칸이 있으면 채우고 진행한다.** 관행이나 전례를 규정 대신 쓰지 않는다.
"작년에도 했다"는 근거가 아니다.

## 3단계 — 사전 승인과 기록

- **사전 승인이 원칙이다.** 사후 보고는 예외 처리이지 절차가 아니다
- 기록에 남길 것: 대상(회사·부서·직급), 사유, 품목, 금액, 시점, 승인자
- **회사 대 회사로 한다.** 수령처는 개인이 아니라 부서·회사
- 상대 회사에 사전 고지가 필요한지 확인한다. 많은 고객사가
  수령 시 자사에 신고하도록 정하고 있다

## 실무에서 자주 걸리는 것

- **명절 선물의 관성.** 매년 보냈다는 이유로 대상과 금액을 그대로 유지하는 것.
  대상 회사의 정책이 바뀌었을 수 있으므로 매년 다시 확인한다
- **개인적 관계와의 혼동.** 오래된 관계라도 거래 상대인 한 규정이 적용된다
- **행사 초청.** 교육·세미나 성격이면 가능한 경우가 많지만
  숙박·항공·동반자가 붙으면 성격이 달라진다. 항목별로 판단한다
- **소액의 반복.** 한 건은 한도 안이지만 누적되면 문제가 된다.
  같은 대상에 대한 연간 누계를 관리한다

## 규칙

**애매하면 하지 않는다.** 이 영역에서 "괜찮을 것 같다"는 근거가 아니다.
판단이 서지 않으면 법무·준법 부서에 묻고, 답이 오기 전에 진행하지 않는다.

**기록할 수 없는 것은 하지 않는다.** 이 한 문장이 대부분의 사고를 막는다.

**이 스킬은 금액 한도, 우회 방법, 기록을 줄이는 방법을 만들지 않는다.**
규정을 피해 가는 구성(분할 지급, 제3자 경유, 명목 변경)을 제안하지 않는다.
그런 요청이 오면 그렇게 할 수 없다고 답하고, 규정 안에서 가능한 대안을 제시한다.

**대신 승인하지 않는다.** 이 산출물은 검토안이고, 승인은 승인권자가 한다.

**선물·접대 이력은 민감 정보다.** 고객 프로파일이나 영업 자료에 섞지 않고
별도로 관리한다 — [[customer-data-handling]], [[customer-profile]].
