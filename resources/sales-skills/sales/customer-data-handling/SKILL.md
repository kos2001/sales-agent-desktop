# 고객 데이터 취급 규칙

## 언제 쓰나

**항상.** 다른 영업 스킬이 모두 이 규칙 아래에서 동작한다. 고객 정보가 한 글자라도
등장하는 작업이면 여기 규칙이 우선한다.

## 이 앱의 보호 장치와 그 한계

새 대화는 **개인정보 보호가 켜진 상태로 시작**한다. 켜져 있으면 메시지를 보내기 전에
로컬에서 정형 식별자를 토큰으로 바꾸고, 응답을 받은 뒤 원래 값으로 되돌린다.

보호가 잡는 것:

| 항목 | 예 |
|---|---|
| 이메일 | `hong@acme.co.kr` |
| 주민등록번호 | `900101-1234567` |
| 사업자등록번호 | `123-45-67890` (체크섬 검증) |
| 전화번호 | `010-1234-5678`, `02-123-4567` |
| 카드번호 | Luhn 검증 통과분 |
| 계좌번호 | 은행명이 앞에 붙은 형태 포함 |
| IP 주소 | |

**보호가 잡지 못하는 것 — 이게 중요하다:**

- **사람 이름과 회사명.** 정형 패턴이 아니라 탐지되지 않는다. `김철수 부장`은
  그대로 나간다.
- **주소, 직책, 조직도** 같은 자유 서술.
- **첨부 파일과 이미지 안의 내용.** 스캔하지 않는다.

그래서 이름과 자유 서술은 **사람이 판단해서 걸러야 한다.** 보호가 켜져 있다는 이유로
안심하고 붙여넣으면 안 된다.

## 규칙

**1. 최소한만 넣는다.** 작업에 필요 없는 식별자는 애초에 대화에 넣지 않는다.
"이 고객 견적 검토해줘"에 주민번호가 필요한 경우는 없다.

**2. 되풀이해 쓰지 않는다.** 사용자가 준 식별자를 응답에서 그대로 반복하지 않는다.
`hong@acme.co.kr`이 입력에 있었어도, 답변에서는 "담당자 이메일"로 지칭한다.
꼭 필요하면 마지막 4자리만.

**3. 산출물에 남기지 않는다.** 제안서·메일 초안·요약 노트에 주민번호, 카드번호,
계좌번호는 **어떤 형태로도** 들어가지 않는다. 부분 마스킹도 넣지 않는다 —
필요하면 "별도 안전 경로로 전달"이라고 쓴다.

**4. 이름은 역할로 바꿀 수 있는지 먼저 본다.** 사내 공유용 요약이라면
`김철수 부장` 대신 `구매팀 결재자`로 충분한 경우가 많다. 충분하면 그렇게 쓴다.

**5. 의심스러우면 묻는다.** 이 값을 넣어도 되는지 판단이 안 서면, 넣지 말고
사용자에게 확인한다. 되돌릴 수 없는 쪽은 전송이다.

## 사용자에게 경고해야 하는 상황

다음이 보이면 작업을 계속하기 전에 짧게 알린다:

- 주민등록번호가 등장 — 영업 업무에서 필요한 경우는 거의 없다. 왜 필요한지 확인.
- 카드·계좌번호가 등장 — 결제 정보는 이 경로로 다루지 않는다.
- 고객 명단 파일 전체를 붙여넣음 — 이번 작업에 필요한 행만 쓰도록 제안.
- 보호가 꺼진 상태에서 식별자가 등장 — 보호를 켜고 다시 보낼 것을 권한다.

경고는 한 문장으로 하고, 작업은 계속한다. 훈계하지 않는다.
